# مصروفاتي — مساعد مالي شخصي محلي بالكامل

تطبيق Android محلي بالكامل (Kotlin + Jetpack Compose + Room + SQLCipher).
يقرأ رسائل SMS وإشعارات تطبيقات البنوك، ويسجّل العمليات تلقائيًا، وبيبني
عليها متابعة مالية كاملة: مصروفات ودخل وتحويلات واسترداد، حسابات وجهات
وميزانيات، مقارنة شهرية وتوقّع ورؤى، دوريات واشتراكات وأقساط، تقارير
ونسخ احتياطي وقفل بالبصمة. كل البيانات على الموبايل فقط — مفيش سيرفر
ومفيش إنترنت مطلوب.

## اللي التطبيق بيعمله

| المجال | التفاصيل |
|---|---|
| الفلوس | وحدات صغرى صحيحة (`Long`) في كل حساب — مفيش `Double` في أي مسار مالي |
| أنواع الحركات | مصروف / دخل / تحويل / استرداد. التحويل مش مصروف، والاسترداد بيقلّل الصرف |
| البحث | بحث ونص وفلاتر (تاريخ، نوع، فئة، جهة، حساب، بنك، مصدر، مدى مبلغ) وترتيب |
| الجهات | تطبيع أسماء، تحليلات لكل جهة، وتعلّم "الجهة دي فئتها كذا" بطلب صريح |
| الميزانيات | ميزانية كلية + ميزانية لكل فئة بحالات آمن/تحذير/تخطي وتنبيهات استباقية |
| التحليلات | متوسط يومي، توقّع نهاية الشهر، مقارنة شهرية بالفئة، رؤى، كشف حركات شاذة |
| الالتزامات | دوريات بكل التكرارات، اشتراكات، أقساط (من غير عدّ مزدوج للمشترى) |
| التقارير | CSV لكل تقرير + PDF كامل، ونص رسائل البنك مش بيتصدّر إلا بطلب صريح |
| الأمان | قاعدة بيانات مشفّرة، قفل بـ PIN (PBKDF2) أو بصمة، ومركز خصوصية بيوصف الواقع |
| المساعد | "اسأل عن مصروفاتك" — محلي بالكامل، بيقرا أرقام محسوبة ومش بيحسب فلوس |

التفاصيل المعمارية وقرارات كل مرحلة في `docs/superpowers/specs/`.

## خطوات التشغيل (Android Studio)

1. افتح Android Studio (نسخة Koala 2024.1 أو أحدث).
2. File → Open → اختار فولدر `ExpenseTracker` ده كامل.
3. سيب Gradle يعمل sync (أول مرة هياخد وقت لتحميل الـ dependencies).
4. وصّل موبايلك بالـ USB وفعّل "USB debugging" من Developer Options،
   أو استخدم أي طريقة تانية لتثبيت APK.
5. اضغط Run (▶) — هيتثبت التطبيق على موبايلك مباشرة من غير ما يعدي
   على أي متجر.

### بناء APK تقدر تنقله لموبايل تاني
Build → Build App Bundle(s) / APK(s) → Build APK(s).
الملف هيطلع في `app/build/outputs/apk/debug/app-debug.apk` — انقله على
الموبايل وثبته (لازم تفعّل "تثبيت من مصادر غير معروفة" أول مرة).

## أول تشغيل

1. التطبيق هيطلب إذن قراءة الرسائل (RECEIVE_SMS) — لازم توافق عشان
   يشتغل تلقائيًا.
2. من أيقونة الإعدادات فوق، افتح **"قواعد الرسائل"** — هتلاقي 4 قواعد
   افتراضية (الأهلي، CIB، بنك مصر، InstaPay) بصيغ تقريبية.
3. **مهم جدًا:** افتح كل قاعدة واضغط "اختبار على رسالة حقيقية"، الصق
   نص أي رسالة وصلتك فعلًا من بنكك (النص ده بيفضل على موبايلك بس ومش
   بيتبعت لحد)، وشوف هل المبلغ والجهة اتقروا صح. لو لأ، عدّل الـ Regex
   لحد ما يظبط بالظبط، لأن كل بنك له صياغة مختلفة شوية.

## كيف يشتغل تقنيًا

- `SmsReceiver` يمسك أي SMS جديدة عن طريق `BroadcastReceiver`.
- `SmsParser` يجرب كل قاعدة مفعّلة: يتحقق من المرسل، بعدين من وجود
  كلمة دالة على خصم (سحب/شراء/تحويل)، بعدين يستخرج المبلغ والجهة
  بالـ Regex.
- لو المبلغ اتقرا بس الجهة لأ، المصروف بيتسجل لكن بعلامة "غير مؤكد"
  عشان تراجعه بنفسك من الشاشة الرئيسية.
- كل القواعد متخزنة في قاعدة بيانات Room محلية، وتقدر تضيف/تعدّل/تحذف
  أي قاعدة من التطبيق نفسه من غير ما تحتاج تعدّل كود.

## المعمارية

```
UI (Compose)  ->  ViewModel  ->  domain/ (دوال صافية)  ->  Repository  ->  DAO  ->  Room
```

- `domain/` مفيهاش أي import من أندرويد: الفلوس، الميزانية، التوقّع، المقارنة،
  الرؤى، كشف الشاذ، التصنيف، التكرار، والمساعد — كلها قابلة للاختبار على JVM.
- كل التحليلات تجميعات SQL (`SUM`/`GROUP BY`) مع أعمدة مفهرسة، مش تحميل كل
  الحركات في الذاكرة — التطبيق بيفضل سريع مع عشرات الآلاف من الحركات.
- نسخة قاعدة البيانات 7، وكل الترقيات حقيقية بتحافظ على البيانات
  (`MIGRATION_5_6` و `MIGRATION_6_7`) — مفيش destructive migration للنسخ 5+.

## النسخ الاحتياطي

من الإعدادات: "حفظ نسخة" بتكتب ملف JSON في المكان اللي إنت تختاره، و"استرجاع
نسخة" بتقرا الملف وتستبدل البيانات في transaction واحدة (لو الملف تالف، بياناتك
الحالية بتفضل زي ما هي). ملف النسخة نص عادي — احفظه في مكان آمن.

## الخصوصية

الرسائل بتتقرا وتتحلل على الموبايل بس. مفيش أي اتصال بالإنترنت في
كود التطبيق، ومفيش رفع بيانات لأي مكان. قاعدة البيانات مشفّرة بـ SQLCipher
ومفتاحها محمي بـ Android Keystore. المساعد المالي شغّال محليًا بقواعد
محدّدة سلفًا — مفيش أي نموذج ذكاء اصطناعي ومفيش مفتاح API.
